# 超级管理员指南

超级管理员拥有全部工单审批权，并负责服务器、凭据、系统设置和用户角色。

## 接入服务器

1. 进入“服务器与凭据”，在凭据页签创建只写密码或私钥。
2. 切换到服务器页签，新建记录并关联凭据。
3. 点击“获取指纹 / 测试并保存”；首次只读探测会显示候选 SSH 指纹，不会自动保存。
4. 通过目标机控制台或其他可信渠道核对，点击“填入指纹字段”后再次测试保存，再执行基础初始化。

“新账号默认用户组”仅用于“申请服务器账号”的审批开通：多个普通组用英文逗号分隔，系统会在目标机补建缺失组并同时加入 `nrm_managed`。转移已有账号不会自动加入这些组；`sudo`、`wheel`、`docker` 必须由用户单独申请并由超级管理员审批。

从服务器创建页进入“新增凭据”时，保存后会自动返回服务器创建页；凭据列表与编辑继续复用 Django Admin。

服务器详情提供 CPU/内存/磁盘概览、受管用户、可接管用户、账号状态切换和附加组调整。“测试连接”“刷新”“执行初始化”均为需要 CSRF 校验的操作按钮。设备概览和用户状态由页面分区异步读取，不会阻塞详情页外壳；用户、用户组和可接管名单在缓存未命中时由一次 SSH 快照统一获取。

## 权限管理

- 用户的 `is_staff` / `is_superuser` 通过 Django Admin 管理。
- 普通管理员与服务器的绑定在“系统设置”中维护。
- `sudo`、`wheel`、`docker` 均按 root 等价权限处理，只能由超级管理员批准。
- NRM 当前不提供临时 sudo、到期自动撤权或资源配额。

## 系统设置

- GitCode：启用开关、OAuth Client ID/Secret 和回调基准地址。
- 邮件：SMTP 或邮件 Webhook 二选一；SMTP 保存前必须完成验证码验证。
- Webhook：全局 Hook 接收全部申请事件，管理员个人 Hook 只接收有权审批的事件。
- 公告：受控 Markdown 子集在平台首页展示，并可推送到目标机 motd。

所有 Webhook 只允许公网 HTTPS。秘密字段编辑时不回显，留空表示保留原值。

## 删除数据

工单是审计记录：删除用户后工单仍保留申请人快照。删除服务器后工单的目标服务器引用置空；正在被服务器引用的凭据受 `PROTECT` 保护，必须先解除引用。
